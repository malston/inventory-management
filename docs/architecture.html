System architecture

Factory Inventory Management

A Vue 3 single-page app that reads from a FastAPI server. The server loads JSON files into memory at startup and filters them per request. There is no database, no authentication, and nothing is written back.

6 routed views 14 GET endpoints 7 JSON data files 250 orders · 32 SKUs · 3 warehouses

Data flow: changing a filter on the Dashboard

  1. ClientA <select> in FilterBar.vue changes. v-model writes the shared ref, for example selectedLocation, in useFilters.js.
  2. ClientA watch on the four filter refs in Dashboard.vue calls loadData().
  3. ClientgetCurrentFilters() returns {warehouse, category, status, month?}. loadData() runs getDashboardSummary, getOrders, getInventory and getBacklog in one Promise.all.
  4. Networkapi.js builds URLSearchParams, leaves out any value of 'all', and sends GET requests to http://localhost:8001/api/….
  5. ServerThe route handler runs apply_filters() and filter_by_month() over the in-memory lists from mock_data.py. Warehouse matches exactly; category and status ignore case.
  6. ServerFastAPI validates list responses against the Pydantic response_model and returns JSON.
  7. ClientResults land in refs (summary, allOrders, inventoryItems, allBacklogItems). Computeds such as statusData and categoryData rebuild.
  8. ClientThe template re-renders the SVG donut and the CSS width bars.

Known gaps

Broken at runtimeMismatch or tech debt

Task and purchase order calls fail

api.js calls /tasks and /purchase-orders, but the server has no such routes. App.vue catches the task error and only logs it.

PurchaseOrderModal is missing

Dashboard.vue renders <PurchaseOrderModal>, but the component is not imported and no file exists.

API URL is hard-coded

localhost:8001 appears in api.js and again in Reports.vue. No Vite proxy and no env config.

Filters are applied unevenly

Demand, backlog, spending and reports take no server filters. Some views narrow by SKU in the browser; Reports ignores filters.

Unused code paths

Backlog.vue has no route, orderTrendData is never rendered, and the PurchaseOrder models are unused.

Docs drift

tests/README.md lists a missing test_orders.py. generate_data.py uses categories that differ from the data files.
